Names from the interface contract (§2.1):

- `eta_app.app`, module-level `eta_app.model`; model path from `ETA_MODEL`, default `data/eta_v1.joblib`.
- `eta_mlflow.register()`, `decide(prod, cand, **thresholds)`, `promotion_gate(**thresholds)`; tracking URI from `MLFLOW_TRACKING_URI`, default `sqlite:///mlflow.db`.
- `eta_ray.build(weight=0.1, extra_work_ms=0.0)`; route `POST /v1/models/eta:predict`, body `{"customer_id": ..., "instances": [...]}`.
- `smoke_eta.py --url ... --expect-version ... [--max-p95-ms 80]`; `--url` can be the server root or the full predict URL.

One interpretation to know about: in `decide()`, `max_slice_regression` is read as a
fraction of prod's slice MAE (0.05 = at most 5% worse), the same convention as
`min_rel_gain`. The report explains why.

Data and model files are not included. They are regenerated by `python eta_data.py` (see
Setup below). Every command runs from the repo root.

## Setup

Tested with Python 3.12 on Linux.

    python3.12 -m venv .venv && source .venv/bin/activate
    pip install -r requirements.txt
    python eta_data.py
    python -c "import pandas as pd, eta_data; pd.read_csv('data/eta_fresh.csv')[eta_data.FEATURES].head(200).to_csv('data/eta_sample.csv', index=False)"

## Part A

    pytest partA -q
    ETA_MODEL=data/eta_v1.joblib uvicorn --app-dir partA eta_app:app --port 8000
    # second terminal
    python load_test.py --url http://localhost:8000/v1/models/eta:predict --data data/eta_sample.csv \
        --concurrency 1 2 4 8 16 --duration 4 --out partA/loadtest_results.json
    python load_test.py --url http://localhost:8000/v1/models/eta:predict --data data/eta_sample.csv \
        --concurrency 1 --duration 4 --batch 100

The two-worker run adds `--workers 2` to the uvicorn command. The pinned runs in the report
prefix the server with `taskset -c 0` (or `0,2`) and the generator with `taskset -c 4-11`.

## Part B

The venv must be activated: `mlflow models serve` starts `uvicorn` by name from `PATH`,
and it exits with code 127 if the venv's `bin/` isn't on it.

    export MLFLOW_TRACKING_URI=sqlite:///mlflow.db
    pytest partB -q
    python partB/eta_mlflow.py register          # versions 1 (v1, alias prod) and 2 (v2, alias candidate)
    python partB/eta_mlflow.py gate
    python partB/eta_mlflow.py gate --min-rel-gain 0.60
    mlflow models serve -m "models:/eta-model@prod"      -p 5101 --env-manager local &
    mlflow models serve -m "models:/eta-model@candidate" -p 5102 --env-manager local &
    python partB/shadow.py --alias-demo          # alias is restored at the end

Running `register` again on an existing `mlflow.db` adds versions 3 and 4 and moves the
aliases to them. Delete `mlflow.db` and `mlruns/` for a clean start.

## Part C

    python partC/verify_ray.py              # checks (a)-(e), about 1 minute
    python partC/verify_ray.py --autoscale  # adds the ~75 s autoscaling run

`verify_ray.py` starts its own Ray (`num_cpus=2`) and Serve on port 8100 and shuts both
down at the end. If an earlier run was killed halfway, run `ray stop --force` first.
